# Models and fields
{: .no_toc }

1. TOC
{:toc}

A `model` is a table. Each line in it is a field: a column, or a relation to another model.

```hana
/// Products in the catalog
model Product {
  id          Int      @id @default(autoincrement())
  sku         String   @unique @db.NVarChar(40)
  name        String
  description String?  @db.NClob
  price       Decimal  @db.Decimal(15, 2)
  stock       Int      @default(0)
  active      Boolean  @default(true)
  attributes  Json?
  createdAt   DateTime @default(now()) @map("CREATED_AT")
  updatedAt   DateTime @updatedAt @map("UPDATED_AT")
  category    Category @relation(fields: [categoryId], references: [id])
  categoryId  Int

  @@index([categoryId])
  @@map("PRODUCTS")
}
```

## Names

hana-orm always quotes identifiers, so names are case-sensitive in HANA:

- The table name is the model name (`Product` → `"Product"`) unless `@@map("PRODUCTS")` says
  otherwise.
- The column name is the field name (`createdAt` → `"createdAt"`) unless
  `@map("CREATED_AT")` says otherwise.

{: .tip }
HANA folds unquoted identifiers to upper case. If you or other tools write SQL by hand, map
tables and columns to upper-case names (`@@map("PRODUCTS")`, `@map("CREATED_AT")`) so that
`SELECT created_at FROM products` works without quotes. In code you keep the camelCase names.

Model names must be unique, start with a letter and contain letters, digits and `_`. Field
names follow the same rules and must be unique within the model.

## Scalar types

| type | default HANA column | TypeScript |
|---|---|---|
| `String` | `NVARCHAR(5000)` | `string` |
| `Int` | `INTEGER` | `number` |
| `BigInt` | `BIGINT` | `bigint` |
| `Float` | `DOUBLE` | `number` |
| `Decimal` | `DECIMAL(38,10)` | `string` (configurable) |
| `Boolean` | `BOOLEAN` | `boolean` |
| `DateTime` | `TIMESTAMP` | `Date` |
| `Bytes` | `BLOB` | `Buffer` |
| `Json` | `NCLOB` | JSON value |
| an enum | `NVARCHAR(255)` | the enum's union type |
| `Unsupported("ST_GEOMETRY")` | the given type | not exposed |

Pick another HANA type with a `@db.*` attribute: `@db.NVarChar(320)`, `@db.Decimal(15, 2)`,
`@db.SmallInt`, `@db.Date`, … The full list is on [Type mapping](types.html).

## Optional fields

`String?` is a nullable column; reads return `string | null`, and `create` may leave the field
out. A field without `?` is `NOT NULL` and must be given in `create` unless it has a default or
`@updatedAt`.

## Field attributes

| attribute | meaning |
|---|---|
| `@id` | primary key (single field); `@id(map: "PK_NAME")` names the constraint |
| `@unique` | unique constraint; `@unique(map: "UQ_NAME")` |
| `@default(…)` | default value, see below |
| `@updatedAt` | set to the current time by the client on every `create` and `update` |
| `@map("COLUMN")` | column name |
| `@db.Type(args)` | native HANA type |
| `@relation(…)` | relation details, see [Relations](relations.html) |
| `@ignore` | keep the column for migrations but hide it from the client, see [Ignoring](ignoring.html) |

The [formatter](multi-file.html#formatting) writes them in this order:
`@id @default @unique @updatedAt @ignore @relation @map @db.*`.

## Defaults

| default | allowed on | how it works |
|---|---|---|
| `@default(autoincrement())` | `Int`, `BigInt` | identity column (`GENERATED BY DEFAULT AS IDENTITY`); the client reads the new value back |
| `@default(now())` | `DateTime` | column default `CURRENT_UTCTIMESTAMP`; the client sends the time when the field is left out |
| `@default(uuid())` | `String` | the client generates a UUID v4 |
| `@default(cuid())` | `String` | the client generates a CUID |
| `@default(sequence("NAME", start: 1, increment: 1))` | `Int`, `BigInt` | the client inserts `"NAME".NEXTVAL`; migrations create the sequence; see [sequences](indexes-constraints.html#sequences) |
| `@default(dbgenerated("SQL"))` | any | a raw SQL default in the DDL; the client leaves the column out of inserts and reads it back |
| `@default(42)`, `@default("open")`, `@default(true)` | matching type | literal column default |
| `@default(ADMIN)` | an enum field | an enum value |

A literal default is also a column default in the database, so rows inserted by other tools get
it too. `uuid()` and `cuid()` exist only in the client.

## updatedAt

`@updatedAt` fields are set by the client on every `create`, `update`, `updateMany` and
`upsert`, also inside nested writes. You can still set them explicitly. Raw SQL and other tools
do not update them.

## Documentation comments

```hana
/// A customer of the shop
model Customer {
  /// Shown on invoices
  name String
}
```

`///` comments become JSDoc in the generated types and `COMMENT ON TABLE` / `COMMENT ON COLUMN`
in the database. `db pull` reads them back. They do not change the contract hash.

## Composite keys

```hana
model OrderItem {
  orderId Int
  lineNo  Int
  sku     String
  qty     Int

  @@id([orderId, lineNo])
}
```

```ts
await db.orderItem.findUnique({ where: { orderId_lineNo: { orderId: 1, lineNo: 2 } } });
```

The key's name in `where` is the field names joined with `_`. Composite keys and other block
attributes are described on [Indexes and constraints](indexes-constraints.html).

## Unsupported types

Columns of types hana-orm does not map (spatial types, `ST_POINT`, …) can be declared so that
migrations and drift checks know about them:

```hana
model Store {
  id       Int                        @id
  location Unsupported("ST_POINT")?
}
```

They are never exposed by the client. A required `Unsupported` column needs a database default,
otherwise the client cannot insert rows.
