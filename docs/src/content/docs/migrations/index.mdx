Migrations change the database step by step, so that every environment reaches the same
schema the same way. In hana-orm a migration is a folder with the literal HANA SQL that runs.

## The workflow

```sh
# 1. change schema.hana
npx hana-orm migrate plan --name add_post_views   # 2. write the migration
git diff migrations/                               # 3. review the SQL
npx hana-orm migrate deploy                        # 4. apply it
npx hana-orm migrate status                        # 5. check
```

```
Created migration migrations/20261120101500_add_post_views with 2 operation(s):
  - Add column "views" to "Post"
  - Create index "IX_Post_views" on "Post" ("views")
Review migration.sql, then run `hana-orm migrate deploy`.
```

Commit the schema and the new migration folder together. Other developers and your
deployment run `migrate deploy` to catch up.

## How it works

- **Planning needs no database.** `migrate plan` compares the `contract.json` of the latest
  migration with the current schema. There is no shadow database.
- **Migrations chain by contract hash.** Each migration records the hash it starts from and the
  hash it ends at. A migration planned on an outdated branch is detected and must be planned
  again on top of the latest one.
- **Each migration runs in one transaction** with transactional DDL
  (`SET TRANSACTION AUTOCOMMIT DDL OFF`). If any statement fails, the whole migration is rolled
  back and the database is as before.
- **Each operation is checked** before and after it runs (a table must not exist before
  `CREATE TABLE`, a column must exist after `ADD`), so a partly changed database is reported
  instead of being changed further.
- **A lock** keeps two deploys from running at the same time.
- **Applied migrations are checksummed.** Editing a migration after it was deployed is reported
  by `migrate status` and stops `migrate deploy`.

## Commands

| command | |
|---|---|
| `migrate plan --name <name>` | write the next migration from the schema change |
| `migrate show [id]` | print the SQL of pending migrations, or of one |
| `migrate deploy` | apply pending migrations |
| `migrate status` | applied, pending, failed and modified migrations; drift; unplanned changes |
| `migrate diff --from … --to …` | compare two states |
| `migrate baseline` | first migration of an existing database, recorded as applied |
| `migrate resolve` | mark a migration as applied or rolled back by hand |
| `migrate unlock` | release a stale lock |
| `migrate squash`, `migrate split` | combine or cut migrations |
| `migrate reset` | development only: drop, re-apply, seed |

All options are listed in the [CLI reference](/hana-orm/tools/cli/#migrations).
