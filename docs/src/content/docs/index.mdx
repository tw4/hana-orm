## At a glance

<Tabs>
  <TabItem label="schema.hana">

```hana
model User {
  id        Int      @id @default(autoincrement())
  email     String   @unique @db.NVarChar(320)
  name      String?
  createdAt DateTime @default(now())
  posts     Post[]
}

model Post {
  id       Int    @id @default(autoincrement())
  title    String
  authorId Int?
  author   User?  @relation(fields: [authorId], references: [id])
}
```

  </TabItem>
  <TabItem label="Query">

```ts
import { HanaClient } from "./generated/hana/index.ts";

const db = new HanaClient();

const users = await db.user.findMany({
  where: { email: { endsWith: "@example.com" } },
  select: { id: true, email: true, posts: { select: { title: true }, take: 3 } },
  orderBy: { createdAt: "desc" },
});
// users: { id: number; email: string; posts: { title: string }[] }[]
```

  </TabItem>
  <TabItem label="Migrate">

```sh
npx hana-orm migrate plan --name init   # writes migrations/<timestamp>_init/migration.sql
npx hana-orm migrate deploy             # applies it in one transaction
```

  </TabItem>
</Tabs>

## Why hana-orm

<CardGrid>
  <Card title="Pure TypeScript" icon="seti:typescript">
    No query engine binary. Queries are compiled to SQL in your process and run through SAP's own
    `@sap/hana-client`.
  </Card>
  <Card title="Types follow the query" icon="approve-check">
    `select`, `include` and `omit` shape the result type, down to nested relations and computed
    fields.
  </Card>
  <Card title="Made for HANA" icon="puzzle">
    Identity columns, `@db.*` native types, several schemas, tenant databases, full-text indexes,
    sequences, HANA Cloud over TLS. `BIGINT` stays exact, `DECIMAL` loses no digit.
  </Card>
  <Card title="Migrations you can read" icon="document">
    Each migration is a folder with the literal SQL that runs. Planning needs no database;
    deploying runs each migration in one transaction, behind a lock.
  </Card>
  <Card title="Two query styles" icon="list-format">
    An object API with nested writes and transactions, and a SQL-like builder with joins,
    subqueries and `WITH`, sharing one client.
  </Card>
  <Card title="Tools around it" icon="laptop">
    `db pull` for existing databases, a local data browser, a formatter, typed SQL from `.sql`
    files and a VS Code extension.
  </Card>
</CardGrid>
